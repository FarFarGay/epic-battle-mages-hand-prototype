# Epic Battle Mages — Handoff в UE5: данж-режим «Blevolord WASD» (отряд гномов)

**Период:** 2026-07-28 … 2026-07-29 (итерация модели 3 «WASD twin-stick»).
**Билд для ревью:** `D:\Hasan\Blevolord_WASD.exe` + `Blevolord_WASD.pck` (нужны оба файла).
**Назначение:** поведенческая спека нового режима для UE-команды — состояния, триггеры, числа. Godot-специфика вынесена в отдельные врезки «Как сделано у нас» и для порта необязательна.

> **Что это за режим.** Отдельный игровой эпизод: игрок управляет НЕ башней, а **малым отрядом гномов** в подземелье. Смена роли — башня геометрически не пролезает в данж, гном мал и смертен. Другие хэндоффы (`handoff_to_ue.md`, `handoff_to_ue_rooms_gameplay.md`) описывают основной геймплей с башней; здесь — только данж-эпизод, он самодостаточен.

> **Статус:** ⭐⭐ **модель управления УТВЕРЖДЕНА как финальная (2026-07-29)** — поиск закончен, данж-эпизод строится на ней. Две предыдущие модели (дрифт-«тачка» с поводком на ЛКМ и пошаговый «Superhot») закрыты и остались в прототипе только как референс; переносить их не нужно. Баланс не финальный — числа даны как рабочие дефолты, петля работает.

## 1. Петля режима за 30 секунд

1. **Предбанник:** игрок руками собирает отряд — раскладывает гномов трёх классов по ячейкам (кап 6).
2. **Вход** (ENTER) — предбанник исчезает, начинается бой.
3. **Бой:** WASD водит группу как одно тело, курсор задаёт направление огня, три кнопки = три класса.
4. **Комната отбита** → выбор одной из трёх карточек-находок (усиление на забег). Второй источник — **сундук** в каждой комнате, стоит в стороне от маршрута.
5. Дверь открывается, идёшь в следующую комнату. Три комнаты ≈ шесть выборов.

**Ощущение:** «веду плотную кучку маленьких бойцов, каждый из которых — и оружие, и жизнь, и расходник».

## 2. Ключевой принцип итерации (важнее любых чисел)

> **Ничто не должно отключать игроку инструмент.**

За итерацию мы трижды наступили на одни грабли и трижды откатились:
- **колчан** (конечные стрелы) — пустой колчан = игрок стоит и ждёт;
- **стамина** копейщиков — то же самое;
- **абсолютный щит** у врага (стрелы не берут вообще) — на поле одни щитовики → лучники бесполезны, игрок бегает кругами.

Каждый раз это давало «ритм» на бумаге и **провал темпа** в руках. Правило, выведенное из этого:

> **Ключ-цель или ресурс меняет ПРИОРИТЕТ инструмента, но никогда не отключает его в ноль.** Игроку всегда должно быть чем действовать прямо сейчас.

Второе правило, того же происхождения:

> **Драйвер должен «тянуть», а не «толкать».** Переключаются не потому, что старое кончилось (простой), а потому что на экране видна причина (цель, которую текущий инструмент не берёт).

## 3. Сбор отряда (предбанник)

Отдельная комната **перед** боевой ареной. По входу в подземелье сносится целиком — реквизит не должен мозолить глаза в бою.

### 3.1 Состав комнаты
- **Три кучки гномов** по классам (лучники / копейщики / артель), в каждой запас **6**.
- **Сетка из 6 ячеек** на полу. Ячейка = слот. **Все заняты — это и есть кап**, без цифр и полосок.
- **Панель параметров** сбоку (единственный UI): показывает силу способностей **от текущего состава** теми же числами, по которым бой считает урон.

### 3.2 Жест «липкая рука» (главное для реализации)
| Действие | Результат |
|---|---|
| Зажать ЛКМ на кучке | Гномы прилипают к руке один за другим, **каждый следующий быстрее** |
| Отпустить кнопку | Гномы **остаются в руке** (столбиком над курсором — видно, сколько взял) |
| Клик по сетке | Рассаживает их по свободным ячейкам |
| Клик мимо сетки | Спрыгивают и бегут обратно на свои места в кучке |
| ПКМ по занятой ячейке | Гном уходит обратно в кучку (удержание вычерпывает с тем же ускорением) |
| ENTER | Вход в подземелье |

Темп набора: первый через `0.28 с`, каждый следующий `× 0.75` (0.28 → 0.21 → 0.16 …). Больше, чем есть свободных ячеек, в руку не набирается.

**Принцип на будущее (когда отряды вырастут):** *единица перетаскивания должна расти вместе с отрядом.* Сейчас тащим гнома; на больших составах поверх ляжет «звено» (готовая связка как один предмет) и «черпак» (провёл по ряду — сгрёб всех). Жест остаётся тот же, меняется зерно.

> **Как сделано у нас.** Комната строится кодом (пол-плита + плитки ячеек), гномы — штатные сцены классов, замороженные статуями (без AI, физики и коллизий). Ячейки — единственный источник правды по составу: и рука, и запасные клавиши 1/2/3 пишут в них, поэтому не расходятся.

## 4. Управление в бою

| Ввод | Действие |
|---|---|
| **WASD** | Движение группы (ведёт точку строя, гномы едут за ней) |
| **Курсор** | Направление огня; вся группа развёрнута к нему |
| **ЛКМ (зажат)** | Полив лучников по курсору |
| **ПРОБЕЛ** | Удар вокруг (копейщики) |
| **ПКМ** | Каменный вал (артель) |
| R / T / E | Читы: рестарт / внеплановая волна / груз |

**Отход спиной стоит темпа.** Множитель скорости по `dot(направление хода, направление прицела)`: вперёд `×1.0`, строго назад `×0.55`, вбок ровно посередине (≈0.78). Тормозится **точка строя**, а не отдельные юниты — группа остаётся одним телом. Кайт спиной перестал быть бесплатным.

### 4.1 Чего сознательно НЕТ
- **Автобоя.** Гномы не стреляют сами по всему, что видят. Гашетка в руках игрока, огонь строго в сектор курсора, за спиной группа не бьёт. Причина от геймдизайнера: *«когда у тебя группа из 10, автобой — это когда тебя никто никогда не поймает»*.
- **Фокус-групп 1/2/3.** Были и выпилены: они существовали только чтобы выдавать приказы разным отрядам, а когда у класса одна кнопка — меню превращается в «жму цифру, чтобы получить право нажать кнопку».
- **Полосок HP/боезапаса.** Состояние читается телами: живые гномы = здоровье, состав = возможности.

## 5. Классы и способности

Отряд смешанный, до 6 гномов. **Класса нет в отряде → нет и его кнопки.**

Билд без мили (только лучники + артель) **разрешён намеренно** — это осознанно тяжёлый выбор, а не ошибка: щитовиков придётся выедать стрелами через щит. Но панель сбора обязана **предупреждать об этом заранее** (у нас — оранжевая строка на нуле копейщиков): цена билда должна читаться до входа, а не выясняться на третьей минуте боя.

### 5.1 Лучники — ЛКМ, полив
- Дальность `12 м`, урон `8–12` за стрелу, темп `0.5–0.9 с`.
- Каждый лучник — отдельный ствол; больше лучников = больше стрел в секунду.
- Стреляют **только** при зажатом ЛКМ и **только** в сектор курсора.
- Выстрел не останавливает бег (полив на ходу — ядро twin-stick-ощущения).

### 5.2 Копейщики — ПРОБЕЛ, удар вокруг
- **Мгновенный** (без замаха): нажал — грохнуло. Замах 0.4 с пробовали и сняли.
- Радиус `6.5 м`, урон `28 × живых копейщиков`, отброс наружу, откат `6 с`.
- Урон направленный (`hit_dir` от центра группы) — добитые рассыпаются «от нас».
- **Между суперами копейщик не воюет вообще** (радиус автоатаки = 0): он тело в строю и одна кнопка. Автоукол пробовали как фон и сняли — любая самодеятельность мили размывает то, ради чего он в отряде.

### 5.3 Артель — ПКМ, каменный вал
- Вал из 5 камней поднимается перед строем и уходит **по прицелу**; направление **фиксируется на запуске** (целиться надо заранее, вал не подруливает).
- Скорость `13 м/с`, дальность `20 м`, полоса `±1.9 м`, урон `45 × живых артельщиков`, отброс `14`.
- Каждую цель бьёт **один раз**. Рассыпается о стену (рейкаст по геометрии) или выдохнувшись.
- Откат `14 с` — **долгий намеренно**: это не расходник на каждую стычку, а «расчистить коридор, когда прижали спереди».

### 5.4 Урон = сумма по живым носителям
Это осознанное решение, а не упрощение: **потеря гнома бьёт по возможностям, а не по абстрактному запасу HP.**

Балансовая точка, которая делает это читаемым: полный расчёт копейщиков (2) сносит щитовика (45 HP) с одного пробела — `28 × 2 = 56 > 45`. Потерял одного — **уже не сносит**. Вот цена потери, без единой цифры на экране.

Урон вала считается **в момент попадания**, а не на запуске: убили артельщика, пока вал летит — вал слабеет на лету.

## 6. Движение группы: «желе-строй»

Требование геймдизайнера: *«движение как единый организм, слегка желеобразный»*. Реализовано **деформацией слотов строя** — само движение юнитов не переписывалось.

Четыре слоя:

1. **Пружина инерции.** Ускорение толкает строй против хода: рванул — тело отстало, встал — накатилось вперёд и качнулось. Затухающий перелёт и читается как желе.
   `offset_vel -= accel × 0.2 × dt` → `offset_vel += (−offset × 32 − offset_vel × 4.2) × dt`, кап смещения `1.2 м`.
   Замер: отставание **~14 см** на разгоне, накат **~10 см** на стопе при шаге строя 75 см.
2. **Вытяжение.** На скорости строй тянется вдоль курса (`+35 %`) и жмётся поперёк (`−16 %`) — капля; на стопе снова круглый.
3. **Волна.** Каждый следующий ряд отстаёт сильнее переднего (`0.13 м` на ряд на полной скорости).
4. **Перетекание.** Голова строя рулит жёстко, хвост вязче (`grip × 0.45` по индексу) — тело перетекает за поворотом, а не крутится доской.

> ⚠ **Грабли, важные для порта.** Считать деформацию нужно от **точки строя** (её ведёт ввод), а НЕ от центроида тел. Через центроид получается обратная связь: слоты двигают гномов → центроид едет → слоты двигают ещё → строй раскачивает сам себя.

### 6.1 Мягкое прибытие к слоту (обязательно)
Подход юнита к слоту не должен быть бинарным «полный ход до порога, потом стоп». Пока группа идёт вперёд, слот убегает от гнома и всё гладко; **на отходе спиной слот наезжает на гнома сзади**, и тот попадает в цикл стоп-старт-перелёт — вся группа мелко дрожит.

Решение: в зоне `1.6 м` до слота скорость гасится пропорционально остатку пути (до 12 % у самого слота).

> ⚠ У нас это вылезало **трижды**, потому что путей движения к слоту оказалось четыре в двух классах (обычный подход и strict-марш у лучника и копейщика, отдельная ветка у артели). При порте: **один расчёт демпфирования, все ветки движения к слоту зовут его.**

## 7. Подача врага: директор давления

Вместо волн по таймеру — **одна кривая: сколько врага должно быть в лицо прямо сейчас**. Директор доливает поштучно и непрерывно, пока живых меньше кривой.

**Почему так.** Прежняя подача (пауза 3 с + скелет идёт от стены 22 м со скоростью 2 м/с ≈ 11 с) давала игроку **первые ~7 секунд ничего не делать**, а 4 скелета с четырёх разных стен приходили по одному. Веселья с первых секунд не было чисто арифметически.

| Параметр | Значение | Смысл |
|---|---|---|
| Стартовая пачка | **7 врагов уже на арене в t=0**, на 9.5 м | Бой начинается на первой секунде, а не на седьмой |
| Кривая давления | 8 → 18 живых за 75 с в комнате | Растёт, пока игрок в комнате |
| Долив | до 3 шт каждые 0.9 с | Кучей, а не по одному |
| Фронт | сектор ±55° от направления «вглубь» | У группы есть перед и спина; отход и фокус-огонь осмыслены |
| Бюджет комнаты | 55 врагов | Выдан и добит → «Волны отбиты ✓», дверь |

Пауз нет вовсе: передышка задаётся провалом кривой, а не мёртвым таймером. Спавн по случайной из четырёх стен (как было раньше) **убивает twin-stick** — пятиться некуда, фокус-огонь бессмыслен.

## 8. Ключ-цели (драйвер переключения между классами)

Враг на экране, которого текущий инструмент не берёт. Подаются **кучей одного типа** (группа щитовиков читается как группа) с гейтом по времени в комнате — первые секунды чистый полив, ключ-цели входят, когда игрок освоился.

### 8.1 Щитовик — зовёт ПРОБЕЛ
- Медленный (`1.5 м/с`), HP 45, щит-плита на груди.
- **Стрелы бьют не в тело, а в ЩИТ:** прочность 45, плита темнеет по мере износа и отваливается — дальше обычный скелет.
- Пробел сносит его целиком (см. §5.4).
- Появляется с 12-й секунды, доля 30 % подачи.

> Первая версия делала щит **абсолютным** («стрелы не берут, и точка») — и это оказалось прямым нарушением правила из §2: когда на поле оставались одни щитовики, лучники выключались и игрок бегал кругами, ожидая откат. Прочность щита возвращает игроку действие: полив всегда даёт прогресс.

### 8.2 Бегун — зовёт разворот / вал
- Быстрый (`4.6 м/с`), хилый (HP 16), заходит **из тыльного сектора**.
- Делает «стоять и лить вперёд» небесплатным.
- Появляется с 20-й секунды, доля 25 %.

Оба типа — **параметризованный обычный скелет** (статы + одна деталь силуэта), новых классов врага заводить не пришлось.

## 9. Карточки-находки (рост внутри забега)

**Не VS-левелапы по опыту.** Причина отказа от них от геймдизайнера: их пришлось бы тащить на этап с башней, где уже есть свой карточный слой (спеллы, чертежи) — «разные балансы, гномы и прочее, это жесть».

Правила:
1. **Живут только внутри данж-забега**, наружу не уходят. В башню, как и раньше, уезжают ресурсы/свитки/чертежи — её баланс не трогается вовсе.
2. Вешаются на **КАТЕГОРИЮ** (все лучники), не на конкретного гнома — иначе микроменеджмент и боль при потерях.
3. **Два источника выдачи:** (а) зачистка комнаты, (б) **сундук** — по одному на комнату, стоит по углам вразнобой, в стороне от маршрута: за находкой надо свернуть, дошёл отрядом (≤2.8 м) — открыл. Комната = уровень; сундуки удваивают число выборов и платят за «полазить», а не за бой. Полоска опыта не нужна вовсе.
   ⚠ Выдача, пришедшая пока окно выбора ещё открыто, должна **встать в очередь**, а не потеряться: у нас зачистка следующей комнаты с невзятой картой сначала пропадала молча.
4. **Лимит 3 на категорию.** Заполнена — её карты больше не выпадают (дефицит слотов = выбор).
5. **Перевес за ПРАВИЛАМИ, а не процентами.** «+15 % чего-нибудь» ощущения не даёт — проверено на колчане и стамине.

Каталог v1 — 9 карт, из них 5 меняют поведение:

| Класс | Карты |
|---|---|
| Лучники | темп +20 % · дальность +4 м · **щитобой ×3 по плите** |
| Копейщики | радиус +2 м · откат −2 с · **выжженная земля после удара** |
| Артель | **+камень с каждой стороны** · **обвал: вал взрывается осколками** · **эхо: через 0.35 с из строя вдогонку идёт второй вал (3 камня, урон вполсилы)** |

> Про эхо: первая версия пускала второй вал **из точки, где разбился первый** — бесполезно, там уже всё зачищено. Правильно — вдогонку из строя; валы живут параллельно.

**Сеты (бонус за 3 карты одной школы) намеренно НЕ делаем:** тройка сама по себе сет. Слой поверх слоя добавим, только если её окажется мало.

## 10. Пазл-загадка (пример подачи без текста)

Котёл в комнате 2: **горловина светится цветом того шара, который нужен прямо сейчас**, и перекрашивается в следующий по рецепту. Правильность — не скрытый флаг предмета, а **совпадение с показанным цветом**; чужой шар выплёвывается и ждёт своей очереди. Подсветка «нужного» шара согласована с кольцом — одна подсказка в двух местах, игрок сверяет цвет, а не запоминает список.

Как образец подачи: **загадка объясняет себя сама, текста не требуется.**

## 12. Порядок реализации (рекомендуемый)

1. **Движение группы** — точка строя + слоты + мягкое прибытие (§6.1). Без него всё остальное дрожит.
2. **Три кнопки классов** (§5) с уроном от состава (§5.4).
3. **Директор давления** (§7) — сразу даёт «весело с первых секунд».
4. **Желе-строй** (§6) — чистая косметика поверх готового движения, но именно она делает группу «телом».
5. **Ключ-цели** (§8).
6. **Сбор отряда** (§3) — самостоятельный экран, можно параллельно.
7. **Карточки** (§9) — последними, когда бой уже приятен.

## 13. Что уже отвергнуто (не изобретать заново)

| Отвергнуто | Почему |
|---|---|
| Колчан (конечные стрелы), стамина копейщиков | Сухой счётчик даёт не решение, а простой — темп проваливается |
| Автоогонь на 360° | При группе из 10 игрока «никто никогда не поймает» |
| Фокус-группы 1/2/3 | Когда у класса одна кнопка, выбор группы — пустой интерфейс |
| Абсолютный щит у врага | Выключает лучников целиком (см. §8.1) |
| Замах 0.4 с у ПРОБЕЛА | Кнопка должна отвечать мгновенно |
| Веер бросков копейщиков в цель | Читалось как «копейщики побежали ко врагу»; они бьют с места |
| Автоатака копейщиков между суперами | Размывает смысл класса-кнопки |
| Эхо из точки разрушения вала | Бесполезно — там уже пусто |
| VS-левелапы по опыту | Пришлось бы тащить на этап башни, конфликт балансов |
| UI-панель по центру на сборе | Перекрывала ровно ту площадку, которую щупаешь |
